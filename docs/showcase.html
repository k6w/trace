    The thesis

    One colour tells you nothing

    A HAR file records seven separate phases for every request: how long it queued, how long DNS took, how long the socket took to open, the TLS handshake, the upload, the wait for the first byte, and the download.

    Six of those are things you can fix. One of them is usually all of them. If the timing bar is a single block of colour, you cannot tell which — and that is how almost every HAR viewer draws it, Trace's first pass included.

    So each phase now gets its own place on one ordered ramp: cool while the connection is being built, hot amber while you wait on a server, green when bytes finally arrive. Learn the ramp once and you read a capture the way you read a score. A wall of amber means the backend is slow. A wall of violet means you are renegotiating TLS you should be reusing. A wall of green means you are shipping too many bytes.

    Plate 02

    Overview now leads with where the time went, because that is nearly always the question. Selecting a row used to paint it solid amber underneath amber text, which made the row you had just chosen the only unreadable one on screen; selection is now a rail and a whisper of tint, and the timing bar survives it.

    Plate 03

    Phases are laid out cumulatively, so each bar sits where it actually happened in the request rather than flush-left like a bar chart. Every phase carries a plain-language description, and the one that ate the request is named outright: waiting for the first byte — this one cost you 1.74 s.

    Repairs

    What was actually broken

    The identity was already strong. What needed work was the information design — and a handful of defects that had shipped with it.

    Symptom Kind Cause, and the fix
    Seven phases, one colour Design Five of the seven phase colours were shades of the same amber, so the bars carried no phase information at all. One ordered spectrum now lives in src/lib/phases.ts, and the waterfall, inspector, legend and landing demo all draw from it.
    METHOD and URL collided Bug The header row and the data rows each declared their own grid template, and the two had drifted apart. Both now read one exported constant.
    The selected row went unreadable Bug Selection filled the row with amber while its children kept amber and muted text colours. Selection is now a rail plus a light tint, so the row — and its timing bar — stays legible.
    Hover turned rows olive Bug hover:bg-primary/30 over a dark ground. Replaced with a neutral tint that does not fight the bars.
    The page blurred behind the inspector Bug The backdrop dropped its background at the large breakpoint but kept its backdrop-blur, so the desktop waterfall went soft for no reason. The blur is now dropped with it.
    Rows re-animated while scrolling Bug Virtualized rows carried a per-index entrance animation, so they faded in again every time they were recycled. Removed.
    A missing favicon and an undefined class Bug index.html pointed at a /favicon.svg that was never committed, and App.tsx carried a mesh-bg class no stylesheet defined. Both now exist.
    Two colour systems competing Design Resource types borrowed the same hues as the phase ramp, so cyan meant both DNS and CSS. Type is now read from a three-letter chip and its colour dropped to a low-chroma hint, leaving saturated colour to the phases.
    Circles in a squared-off design Design Radius tokens resolved to zero everywhere except rounded-full, which kept a scatter of dots circular. All corners are square now.

    Privacy

    It never leaves the tab

    HAR files are not harmless. They hold every header of every request — session cookies, bearer tokens, API keys, and whatever was in your request bodies. Pasting one into an online viewer hands all of that to someone else's server.

    Trace is a static page. Parsing happens in your tab through the File API. Open your own DevTools network panel while you use it and you will see exactly one request: the page itself.
